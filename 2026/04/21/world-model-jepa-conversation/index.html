从 I-JEPA 到世界模型：一场算法对话的记录

写在前面

前段时间和 AI 进行了一场关于世界模型和 JEPA（Joint-Embedding Predictive Architecture）的长对话。从”I-JEPA 和 MAE 有什么区别”这个看似简单的问题出发，一路聊到了 EMA 防止坍塌的数学直觉、Predictor 被丢弃的工程哲学、世界模型在具身智能中的基础设施地位，以及 LLM 与 JEPA 协作时的边界与互补。

这篇文章是对那场对话的整理和重构，剥离了后来进入具体工程场景的讨论，只保留算法层面的核心脉络。我尽量保留对话中那些精彩的比喻——海盗寻宝、皮影戏、婴儿学抓杯子——因为它们真的把抽象概念讲活了。

零、JEPA 是什么

在深入对比之前，先花两分钟说清楚 JEPA 到底是什么。

JEPA 全称 Joint-Embedding Predictive Architecture，中文叫联合嵌入预测架构，由图灵奖得主 Yann LeCun（杨立昆） 提出。它是 LeCun 构想的”世界模型”理论的核心技术载体。

核心思想：在”脑子里”预测，而不是在”视网膜上”预测

传统自监督方法（如 MAE、BERT）做的是重建：遮住输入的一部分，让模型把缺失的像素或token补回来。这相当于要求模型做”超分辨率修图”或”完形填空”。

JEPA 做的则是预测：遮住输入的一部分，让模型在表征空间（embedding space）里预测被遮住内容的抽象特征，而不是重建原始像素。

传统自编码器（MAE/BERT） JEPA
预测对象 原始输入（像素/token） 抽象表征（embedding）
操作空间 感官空间 概念空间
学到的能力 “长什么样” “是什么 + 会怎样”
与世界模型的关系 主要是特征提取器 世界模型的核心架构

JEPA 家族

  • I-JEPA：Image-JEPA，在静态图像上验证”表征预测”思想（Meta/FAIR，2023）
  • V-JEPA：Video-JEPA，在视频上训练，预测时空表征（Meta/FAIR，2024）
  • 完整 JEPA 蓝图：LeCun 2022 年论文中提出的自主机器智能完整架构，包含感知、世界模型、代价模块、行动器等

本文讨论的主要是 I-JEPA（图像版）的技术细节，以及这些细节如何映射到 LeCun 的世界模型宏大框架中。

一、像素重建 vs 表征预测：MAE 和 I-JEPA 的根本分野

对话的起点是一个看似简单的问题：I-JEPA 和 MAE 都是基于掩码的自监督方法，区别在哪？

答案是：预测的目标空间不同。

维度 MAE I-JEPA
预测目标 被 mask 掉的原始像素 被 mask 区域的特征表征
操作空间 像素空间 隐空间/嵌入空间
本质 自编码器 世界模型

MAE 的工作方式是：遮住图像 75% 的区域，编码器处理可见的 25%，然后解码器尝试重建被遮住的具体像素值（MSE 损失）。它学习的是”如何填补像素细节”，更接近低级视觉——一种感官的模仿者。

I-JEPA 则完全不同：它不重建像素，而是训练一个 Predictor，让它在表征空间中预测被 mask 区域的嵌入向量。它学习的是”在抽象层次上预测内容”，而非像素细节——这是认知补全。

简单来说：MAE 关心”被挡住的部分像素是什么颜色”，I-JEPA 关心”被挡住的部分在语义/特征上是什么”。

这个区别不是工程上的偏好，而是世界观的分歧。MAE 是一个优秀的视觉预训练编码器；I-JEPA 是迈向世界模型的一步。

二、I-JEPA 的训练：三个组件的”猜测-验证”游戏

I-JEPA 的核心架构由三个组件组成：

组件 角色 参数是否更新
Context Encoder（输入编码器） 处理可见区域，提取上下文特征 ✅ 梯度更新
Target Encoder（目标编码器） 处理被 mask 区域，提取目标特征（作为正确答案） ❌ EMA 滑动
Predictor（预测器） 基于上下文特征 + 位置信息，”脑补”目标区域的特征 ✅ 梯度更新

训练的单步 forward 流程如下：

  1. 生成 Mask：随机选若干 Target Blocks（要预测的目标区域，完全遮住），再选 Context Block（模型能看到的区域）。
  2. 提取 Target 特征：被 mask 掉的区域送入 Target Encoder，输出 z_target，Stop Gradient——纯粹作为监督信号。
  3. 提取 Context 特征：可见区域送入 Context Encoder，输出 z_context。
  4. Predictor 预测：接收 z_context + Mask Tokens（包含位置信息），输出 z_pred——对目标区域特征的猜测。
  5. 计算 Loss：让 Predictor 的猜测尽可能接近 Target Encoder 给出的标准答案。

最关键的设计是Target Encoder 用 EMA 更新，而非梯度下降。这引出了下一个核心问题。

三、EMA 的”慢”：为什么慢反而有效？

为什么 Target Encoder 要用 EMA（Exponential Moving Average）缓慢更新，而不是直接跟 Context Encoder 共享参数？

先理解：不用 EMA 会发生什么？

假设 Context Encoder 和 Target Encoder 同步优化，Predictor 去预测 Target：

  • Encoder 把所有输入都映射成同一个常数向量 c
  • Predictor 学到恒等映射：输入 c，输出 c
  • Loss = ||c - c||² = 0，完美！

这就是模型坍塌（Collapse）：Loss 降到了 0，但模型什么也没学到。因为在 I-JEPA 中，监督信号本身也来自 Encoder，就有”作弊空间”。

EMA 如何防止坍塌？

EMA 的更新公式：θ_target ← τ·θ_target + (1-τ)·θ_context（τ ≈ 0.996~0.999）

这意味着 Target Encoder 像一个大惯性的飞轮，缓慢跟随 Context Encoder 的历史平均。因为 Target Encoder 变化极其缓慢，Predictor + Context Encoder 无法通过一步梯度下降就让 Target 配合自己坍塌。它们必须真正学会：

  • Context Encoder 提取有意义的上下文语义
  • Predictor 学会空间推理和位置映射

用海盗寻宝的比喻来理解：

你是寻宝队队长，海岛上有个怪脾气的老海盗船长（Target Encoder），他每 3 个月才出一次海挪宝藏。

如果老船长也每天跟着你改藏宝地点，寻宝队和军师可以直接串通：”队长，老船长肯定把宝藏放你今天上午停船的地方。”游戏坍塌了。

正因为老船长慢，他像一块不会配合你演戏的试金石。你无法操纵他，只能让自己的航海术、观星术、读图术变得真材实料。

一句话点题：EMA 的”慢”不是缺陷，而是刻意制造的”公正性”——它让 Target 无法被 Predictor 和 Context Encoder “即时收买”。

四、Predictor：训练时的”脚手架”，推理时的”过客”

如果 Predictor 在训练中如此重要，为什么训练完成后却被丢弃，只使用 Encoder？

Predictor 在训练中承担三个关键职责：

职责一：空间推理的”苦力”
Predictor 必须学会”根据上下文特征 + 目标位置，推断那里是什么”——上下文整合、空间位置映射、语义补全。没有它，Context Encoder 必须直接输出与 Target Encoder 完全一致的特征，这会严重约束 Encoder 的学习空间。

职责二：防止坍塌的”不对称因子”
Predictor 的存在意味着 Context Encoder 不需要直接输出与 Target Encoder 相同的表示，它只需要输出一个”可被 Predictor 转换成 Target 表示“的中间表示。这给了 Context Encoder 极大的自由度，可以学习更丰富、更通用的特征。

职责三：吸收”任务特定偏差”
不同位置、不同尺度的 target block 需要不同的预测策略。Predictor 吸收了这些与具体掩码策略相关的复杂性，让 Context Encoder 专注于学习通用的视觉语义。

为什么训练完可以扔掉？

因为下游任务（分类、检测等）需要的是通用的视觉特征，而不是”预测被遮挡区域”的能力。Context Encoder 已经学到了强大的视觉表示，Predictor 的预测能力对下游任务没有直接帮助。

用皮影戏来比喻：

华北有个皮影戏班子。

  • 老师傅（Target Encoder）：坐在幕后正中央，动作标准，极慢调整姿势。
  • 小徒弟（Context Encoder）：站在幕前，面对观众，手脚灵活，表演必须最终能对应上老师傅的影子。
  • 提线杆（Predictor）：一根复杂的竹竿，勾住小徒弟的四肢，伸向幕后的老师傅。小徒弟的每个动作，都要经过这根竹竿的转换、补偿、纠偏，才能在幕布上投出和老师傅一致的身影。

三年后，小徒弟出师去跑江湖：他直接上台演独角戏，不需要幕后的老师傅了，也不需要那根提线杆了——那杆子是为了对齐老师傅而发明的，不是为观众表演用的。但他三年里练出的身法、眼神、力道（Context Encoder 学到的通用表示），全留在了骨子里。

这就是 Predictor：它是对齐用的翻译器，不是产品本身。

五、世界模型：不是预测像素，而是预测”抽象”

聊完 I-JEPA 的技术细节，自然要问：这些和”世界模型”有什么关系？

LeCun 的核心观点非常反直觉：

真正的智能，不是预测你下一秒会”看到什么像素”，而是预测世界在”抽象层面”会发生什么。

一个球飞过来，你的大脑在干什么？

层次 你在预测什么 对应技术
低级 视网膜上的光斑变化 像素重建（MAE）
中级 球的位置、速度、轨迹 物理特征
高级 “球会弹起来，我得接住” 世界模型的表征预测（I-JEPA）

你不是在预测视网膜的像素变化——那太底层、太脆弱（光照一变就全错）。你预测的是物理世界的状态演化。

MAE 不是世界模型：它在像素空间重建，相当于一个超分辨率修图工具。它学到了”纹理长什么样”，但不理解物体的边界、遮挡关系、物理规律。它只是感官的模仿者。

I-JEPA 是：它在表征空间做预测，相当于在脑子里的概念世界中做推理——“我看到了猫的身体（context），根据我对’猫’这个概念的理解，被挡住的这里应该是猫头（target representation）”。这不再是修图，这是认知补全——和人类看世界的方式一致。

把 I-JEPA 的三个组件映射到 LeCun 的 JEPA 通用框架：

Context Encoder = 感知系统，Target Encoder = 客观现实，Predictor = 世界模型核心。

六、推箱子的哲学：三个组件的精确对应

为了把抽象概念落地，我们用”机器人推箱子”这个具身智能的经典场景来精确对应三个组件。

场景：机器人在房间里，面前 2 米处有个纸箱。机器人要学的任务是：预测”推箱子”这个动作的后果。

1. 感知模块（Context Encoder）

  • 输入：机器人摄像头拍到的当前画面（箱子、地板、墙壁）
  • 输出：当前世界状态的表征 s_t，包含”面前有个箱子”、”箱子大概 50cm 宽”、”地板是光滑的”
  • 相当于机器人的**”当下认知”。它不一定全对（比如可能误判箱子重量），但它是机器人对世界的内部描述**。

2. 世界模型（Predictor）

  • 输入：当前状态 s_t + 动作 a_t：”向前推，力度 5 牛顿”
  • 输出：预测的新状态 ŝ_{t+1}，包含”箱子向前移动了 80cm”、”箱子没有翻倒”
  • 这就是世界模型的核心——它不在真实世界里推箱子，而是在表征空间里**”想象”推完会发生什么**。好的 Predictor 相当于脑子里装了一个物理引擎。

3. 客观参考（Target Encoder, EMA）

  • 输入：机器人真的执行了”推箱子”动作后，摄像头拍到的新画面
  • 输出：真实新状态 s_{t+1}，包含”箱子实际移动了 75cm”——注意！和预测的 80cm 有偏差
  • 这就是 stubborn 的现实。箱子不会因为机器人预测它移动 80cm，就真的移动 80cm。它按物理规律走了 75cm，多一厘米都不会配合。

训练循环：

如果没有 EMA：Target Encoder 也快速跟着 Predictor 变，机器人可以”自欺欺人”——Predictor 预测箱子会飞，Target Encoder 马上配合说”对，飞起来了”→ collapse。EMA 保证 Target Encoder 是”顽固的现实”。

七、完整的决策架构：从”会发生什么”到”该做什么”

世界模型能回答”如果我推箱子，会发生什么”，但机器人怎么知道”下一步应该做什么”？

世界模型本身不决定目标，它只回答”如果我做 X，会发生什么”。要产生行动，需要引入另外两个模块：

LeCun 的完整蓝图（2022 年论文）包括：Perception（感知）、World Model（世界模型）、Cost Module（代价模块）、Short-term Memory（短期记忆）、Actor/Policy（行动器）、Configurator（配置器）。

I-JEPA 训练时动作是随机采样的，目的是让 Predictor 学会”动作→后果”的映射。但真正使用世界模型时，机器人必须有办法回答”我想达成 X，现在该做什么”——这需要 Cost + Inference 的配合。

八、大脑与小脑：JEPA 的精确边界

JEPA 世界模型对应的是大脑皮层，而小脑在标准 JEPA 架构里其实是缺失的一层。

特性 大脑（Cerebrum/Cortex） 小脑（Cerebellum）
速度 慢（100-500ms） 快（10-50ms）
意识 有意识、可报告 无意识、自动化
处理什么 “推箱子会让它移动” “右臂伸 15°、肘屈 8°、力控 5N”
模型层级 抽象认知世界 感觉运动物理

把 JEPA 组件映射到神经解剖：

  • Context Encoder → 视觉皮层 / 顶叶联合区（”看到箱子、门口、距离”）
  • Predictor → 前额叶皮层（”想象推箱子的后果”）
  • Cost Module → 前额叶 + 边缘系统（”哪个动作更靠近目标？”）
  • Target Encoder → 海马体 / 记忆巩固（”存储和提供稳定的经验参考”）

JEPA 本质上训练的是大脑的”前额叶-顶叶回路”——负责感知整合、因果推理、行动后果想象、目标导向规划。

但标准 I-JEPA/V-JEPA 只管到”决定做什么”这一层，不管”怎么精确执行”。从”绕到左侧，向右推”这个高级策略，到”身体转向 30°、右臂伸出、手掌贴合、施加 5N 水平力”这些精确运动指令，中间还差一层——这就是小脑的工作：运动控制、力控、平衡、反射。

目前的机器人系统通常是大脑+小脑分层：

  • 大脑层（LLM/VLM/JEPA）→ 负责”做什么”（What）和”为什么”（Why）
  • 小脑层（强化学习策略/阻抗控制/MPC/运动原语）→ 负责”怎么做”（How）

JEPA 训练完后，只提供了”大脑的感知皮层”（Context Encoder）。一个完整的具身智能体，还需要额外补上代价模块和小脑控制器。

九、”不会”到”会”：世界模型不是先验，而是学出来的

如果高层规划器（大脑/JEPA）本身不会推箱子，怎么完成任务？

答案是：最开始确实不会，而且可能永远学不会”完全正确”——但这恰恰就是智能的常态。

婴儿学抓杯子的真相

阶段 大脑在干嘛 结果
0-3 个月 随机挥舞手臂 十次有九次碰不到杯子
3-6 个月 偶尔碰到，观察到”手靠近 + 肌肉紧绷 → 触感变化” 开始建立粗糙关联
6-12 个月 能抓到，但经常翻倒/太用力 世界模型从大量试错中拟合出”力 vs 结果”的统计规律
1 岁以后 基本能稳定抓取不同形状杯子 模型不完美，但够用

大脑的世界模型不是先验写好的物理公式，而是从海量”动作→结果”的脏数据中统计学习出来的。

闭环修正：不需要一次性算对

智能体用的是**模型预测控制（MPC）**的哲学：

大脑不需要一次性算对。它只需要比”完全随机”好一点点，然后靠高频闭环修正累积出正确行为。

你学骑自行车时，大脑对自行车物理的理解其实极其粗糙——你说不出角动量守恒公式，甚至不知道车把该转几度。但你能骑，因为大脑给方向，小脑和脊髓在毫秒级微调肌肉张力。如果大脑必须”完全会”才能行动，人类永远学不会走路。

十、世界模型真的有用吗？回应”有限”的质疑

如果世界模型只负责预测状态转移，不管决策、不管执行，那它在具身智能里到底有什么实际价值？

先看一个残酷的对比：

能力维度 没有世界模型（纯 Model-Free RL） 有世界模型（JEPA 思路）
学习方式 在真实世界里随机推几千次 推几十次建立直觉，之后大部分试错在脑子里完成
样本效率 需要 10⁶ ~ 10⁸ 次物理交互 需要 10² ~ 10⁴ 次物理交互
遇到新桌子 几乎从头学 能泛化：”更高的桌子 → 杯子滑得更慢”
做错时的反馈 “杯子碎了，负奖励”（事后） “推 3cm 就会到边缘，再推就掉了”（事前预警）
可解释性 黑盒：输入像素→输出电机扭矩 可解释：预测”杯子位置 t+1”，能检查、能验证

差距不是”有点用”，是指数级的。

预测是智能的基础设施：没有世界模型 = 只能反射；有世界模型 = 可以规划。没有世界模型的人 = 新手司机，每次变道都靠本能反应，错了就撞；有世界模型的人 = 老司机，变道前脑子里预演了”后车距离、速度差、并线后的位置”。

世界模型让机器人获得四种”超能力”：

  1. Zero-shot 推理：训练时推过”轻箱子在光滑地板”，没见过”重箱子在粗糙地毯”，但能组合物理直觉，第一次就做出合理预测。
  2. 反事实思考：能回答”如果刚才我用更小的力推，结果会怎样？”——这是归因和纠错的基础。
  3. 多步规划：在脑子里推演”推→滑→停→再推”的完整链条，而不是一步一步试错。
  4. 可解释性：预测的是”箱子会移动到 (x, y)”，而不是黑盒输出一个电机扭矩——可以检查、可以验证、可以安全拦截。

世界模型不是应用层，是基础设施层——就像操作系统看起来不做具体的事，但没有它什么都做不了。

十一、LLM + JEPA：当语义规划遇到物理推演

如果把 LLM（大语言模型）和 JEPA（世界模型）结合起来，前者做任务规划，后者做物理推演，是不是就完整了？

LLM 确实会规划错，而且错得很有”LLM 特色”——一本正经地胡说物理。因为它基于互联网文本的统计模式，缺乏真实物理 grounding：

LLM 的规划 实际问题 后果
“把杯子从桌上推到地上” 没考虑杯子会碎 任务完成，但代价惨烈
“单手抓住箱子底部向上抬起” 没考虑箱子 50kg 电机烧毁/机器人摔倒

JEPA 的角色是 LLM 的”物理校验器”：

JEPA 不是替代 LLM 做规划，而是给 LLM 提供 “物理 reality check”。LLM 是”策略生成器”，JEPA 是”物理验证器”，形成生成-验证-再生成的循环。

如果 LLM 固执己见怎么办？系统设计上需要硬阻断（Safety Filter）：当 JEPA 风险分数超过阈值时，直接拒绝执行并进入安全姿态。

十二、JEPA 在完整架构中的精确边界

最后，精确画出 JEPA 的边界——它到底管到哪、不管到哪。

关键区分：LeCun 的 JEPA 蓝图（完整自主机器智能架构）比 I-JEPA/V-JEPA（具体论文实现）要大。I-JEPA/V-JEPA 只是蓝图中的”世界模型模块”的验证，主要验证的是”表征预测”这个核心思想。

写在最后

这场对话让我对几个之前模糊的概念有了清晰的理解：

  1. I-JEPA 不是 MAE 的改进版，而是完全不同的世界观——从”修图”到”认知”
  2. EMA 的慢不是工程妥协，而是刻意的”公正性设计”——防止被收买
  3. Predictor 的丢弃不是浪费，而是训练脚手架和产品本身的分离
  4. 世界模型不是奢侈品，而是具身智能的基础设施——没有它就只能反射
  5. LLM + JEPA 不是谁替代谁，而是语义规划器和物理校验器的互补

最让我印象深刻的是那个比喻：小徒弟出师后，不需要幕后的老师傅和提线杆了，但三年里练出的身法、眼神、力道，全留在了骨子里。Predictor 是提线杆，Context Encoder 是小徒弟，而我们在下游任务中使用的，正是那个不再需要 scaffolding 的、已经内化了一切理解的表示。
