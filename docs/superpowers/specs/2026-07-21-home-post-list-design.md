# 主页文章紧凑列表设计

**日期：** 2026-07-21  
**状态：** 已确认

## 背景

当前主页使用 Icarus 的通用文章卡片。卡片先显示文章标题，又把正文开头的一级标题包含在摘要中，因此同一篇文章会连续出现两个相近标题。长摘要还会挤占首页空间，不利于快速浏览全部文章。

## 目标

将主页及其分页改成紧凑的文章索引，让读者一眼看到文章标题、发布日期、分类和标签，并能直接进入文章、分类或标签页面。

## 范围

本次只修改首页索引，包括根路径和 `/page/<页码>/` 等分页页面。

分类页、标签页、归档页和文章详情页保持现状。主题依赖目录 `themes/icarus/` 不做任何修改。

## 页面设计

首页主内容区使用一个列表容器。每篇文章对应一个独立列表项，包含：

1. 可点击的文章标题，作为列表项中最醒目的信息；
2. 格式为 `YYYY-MM-DD` 的发布日期；
3. 一个可点击的分类；
4. 若干可点击的标签，以紧凑标签样式排列。

首页不再显示正文摘要、阅读时长、更新时间和“阅读更多”按钮。桌面端允许日期靠右展示，分类和标签位于标题下方；移动端按标题、日期、分类、标签的顺序自然换行，不产生横向滚动。

文章缺少日期、分类或标签时，直接省略对应区域，不显示空占位或兜底文字。标题和已有元数据仍需正常显示。

原有分页组件保留，行为和链接不变。

## 技术设计

在根目录 `scripts/` 中增加独立的 Hexo 扩展，使用 Hexo 的 HTML 渲染过滤器识别 `page.__index`，只处理首页索引页面。扩展根据当前分页的 `page.posts` 生成紧凑列表，并为页面增加首页列表标识。

首页列表的链接通过 Hexo URL helper 生成，以兼容站点根路径、永久链接、分类路径和标签路径配置；输出到 HTML 的标题、分类名和标签名必须转义。

样式追加到现有 `source/css/custom.css`，并以首页列表标识作为选择器前缀。原有 Icarus 文章卡片只在首页隐藏，分页组件保持可见；其他页面不会命中这些样式。

该方案沿用项目已有的根目录 Hexo 扩展和自定义 CSS 机制，避免修改或复制 Icarus 主题源码。若主题升级，只需确认主页主内容容器的类名仍为 `column-main`。

## 数据流

1. Hexo 和 Icarus 正常完成页面渲染；
2. 首页 HTML 过滤器收到当前页面及其 `page.posts`；
3. 扩展为每篇文章生成标题、日期、分类和标签链接；
4. 扩展把紧凑列表加入主页主内容区并标记页面；
5. 自定义 CSS 隐藏主页原文章卡片，只展示紧凑列表和原有分页；
6. 非首页页面原样返回，不进入列表转换。

## 异常处理

- 如果渲染上下文不是首页或没有文章集合，扩展原样返回 HTML；
- 如果找不到 Icarus 主内容容器，扩展记录警告并原样返回 HTML，避免生成损坏页面；
- 单篇文章缺少某项元数据时，只省略该项；
- 所有用户内容先进行 HTML 转义，防止标题或标签中的特殊字符破坏页面结构。

## 验证

运行 `npm run build` 后检查：

1. 首页只显示紧凑文章列表，不显示正文摘要和“阅读更多”；
2. 每篇文章在首页只出现一个可见标题；
3. 标题、分类和标签链接指向正确路径；
4. 首页分页仍然存在并可导航；
5. 没有分类或标签的文章能够正常渲染；
6. 分类页、标签页、归档页和文章详情页仍使用原有布局；
7. 生成页面在桌面和移动宽度下没有明显溢出。

## 非目标

- 不改变每页文章数量或排序；
- 不修改文章 Markdown 内容或摘要生成配置；
- 不重做侧边栏、导航栏和分页视觉；
- 不为分类页、标签页或归档页引入同样的紧凑列表。
