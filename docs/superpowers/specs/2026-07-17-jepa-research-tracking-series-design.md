# JEPA 调研追踪博客系列设计

## 背景与目标

仓库当前有两类 JEPA 内容：

1. `source/_posts/` 中经过主题化写作的原创技术博客；
2. `research/jepa/` 中按日期沉淀的论文调研日报与专题记录。

本次将现有 JEPA 调研记录发布为独立博客系列，并修改 `jepa` 每日自动化，使未来每次运行都完成“研究、成文、验证、提交、推送”的闭环。读者可通过分类、标签和文首声明明确识别“持续研究追踪”，避免与作者自行构思、组织和写作的原创博客混淆。

## 方案比较

### 方案 A：每份研究记录生成一篇完整静态文章（采用）

- 优点：完整保留论文数据、判断与一手来源；Hexo 原生支持，无额外运行时依赖；单篇可搜索、收藏和分享。
- 代价：研究底稿与博客正文会形成两份内容，后续修订需要明确以研究记录为事实源。

### 方案 B：只发布一个系列索引和每日摘要

- 优点：维护量小，重复内容少。
- 缺点：读者无法在博客内获得完整研究结论，不符合“把调研追踪文章变成博客系列”的目标。

### 方案 C：增加 Hexo 插件，在构建时动态导入 `research/jepa/`

- 优点：只有一份正文来源。
- 缺点：引入自定义构建逻辑，front matter、永久链接和主题插件兼容性更复杂；对当前五篇文章而言成本过高。

## 文章元数据约定

所有追踪文章统一使用：

```yaml
categories:
  - JEPA研究追踪
tags:
  - JEPA
  - JEPA追踪
```

- `JEPA研究追踪` 是单一分类，符合项目“一篇文章一个分类”的约定。
- `JEPA追踪` 是区分系列的唯一专用标签；Hexo 会自动生成对应标签聚合页。
- `JEPA` 作为主题标签，仍允许读者从 JEPA 总标签页同时看到原创文章和追踪文章。
- 同日的日报与专题使用不同时间，避免排序相同：日报 `10:00:00`，专题 `18:00:00`。

## 正文结构与标识

每篇文章在 front matter 后增加统一声明：

> 本文属于「JEPA追踪」系列，记录每日论文检索、原文核验与阶段性判断；它保留研究日志的证据密度，与经过主题化重写的原创博客区分。

声明之后保留研究记录全文，不改写实验数字、事实/作者主张/推断边界和来源链接。研究文件继续保留，作为后续自动化去重和修订的事实源。

## 数据流与维护边界

```text
research/jepa/YYYY-MM-DD*.md（事实源）
            ↓ 静态转换并添加统一元数据
source/_posts/YYYY-MM-DD-jepa-*.md（公开博客）
            ↓ Hexo clean + build 验证
JEPA研究追踪分类页 + JEPA追踪标签页
            ↓ 精确暂存当日文件并推送 blog 分支
GitHub Actions 构建并发布站点
```

### 每日自动化发布边界

`jepa` 自动化保留现有检索、去重、一手来源核验与研究记录要求，并增加以下固定步骤：

1. 将当日完整研究记录写入 `research/jepa/YYYY-MM-DD.md`；即使“今日无高可信新增”，也写入包含检索范围、排除结果和原因的简短记录。
2. 同步生成 `source/_posts/YYYY-MM-DD-jepa-research-tracking.md`，正文完整承载当日研究记录，并使用本设计约定的分类、标签和系列声明。
3. 运行 `npm run clean` 与 `npm run build`，确认文章页、`JEPA研究追踪` 分类页和 `JEPA追踪` 标签页生成成功。
4. 仅在当前分支为 `blog` 且构建成功时，精确暂存当日研究记录与当日博客；不得使用会卷入其它改动的宽泛暂存方式。
5. 提交后仅推送 `origin blog`，绝不直接修改或推送 `master`；`public/` 仍是临时构建目录，不纳入版本控制。
6. 若分支错误、构建失败、远端推送失败或检测到当日目标文件之外的待提交内容，停止发布并向用户报告，不以破坏性命令清理工作区。

首次发布时提交五份研究记录、五篇对应博客和本次规划文档；已有未跟踪 `source/_drafts/` 及其它无关文件不纳入提交。

## 验证标准

1. 五篇新文章均存在且包含合法 Hexo front matter。
2. 每篇只有一个分类 `JEPA研究追踪`，并同时带有 `JEPA`、`JEPA追踪` 标签。
3. 现有原创 JEPA 文章内容与标签不变。
4. 研究记录原文件不删除、不改写。
5. `npm run build` 成功，生成文章页面、分类页和标签页。
6. 当前分支确认为 `blog`，暂存区不包含 `source/_drafts/`、`public/` 或其它无关文件。
7. 源文件与规划文档提交到 `blog`，并成功推送 `origin blog`；不直接操作 `master`。
8. `jepa` 自动化提示词已更新为每日生成博客、构建验证、精确提交和推送的闭环。

## 非目标

- 不把研究记录改写成更具叙事性的原创文章。
- 不修改 Icarus 主题文件。
- 不为系列增加自定义 UI、徽章或导航菜单。
- 不把 `source/_drafts/` 或工作区其它改动捎带进自动化提交。
- 不直接修改或推送 `master`。
- 不提交 `public/` 构建产物。
