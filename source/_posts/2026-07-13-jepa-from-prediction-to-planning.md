# 从上一站继续出发

在[上一篇关于 JEPA 与世界模型的文章](/2026/04/21/world-model-jepa-conversation/)里，我把 I-JEPA 的转向概括成一句话：不要执着于还原每个像素，而要在表示空间里预测世界。被遮住的是猫头，模型不必猜中每根毛发，只要在抽象层面知道那里应该是“猫的头部”。

这套思想最有吸引力的地方，是它像一条可以不断向外延伸的路线：从静态图像到视频，从视觉到语言，再从观察世界走向在世界里行动。

最近读到的两篇工作，正好落在这条路线的两个方向上。第一篇是已经成为 [ICLR 2026 Poster](https://iclr.cc/virtual/2026/poster/10010475) 的 [LLM-JEPA](https://arxiv.org/abs/2509.14252)，它把联合嵌入预测引入语言模型；第二篇是 [World Modeling Workshop 2026](https://world-model-mila.github.io/) 的非存档海报论文 [Value-Guided Action Planning with JEPA World Models](https://arxiv.org/abs/2601.00844)，它追问一个更棘手的问题：一个能预测状态变化的潜空间，为什么仍然可能很难用来规划动作？

它们不是前后相接的一套统一系统，研究对象、损失函数和证据成熟度都不同。但把两篇放在一起看，会出现一条比“JEPA 又被用到了哪里”更有意思的主线：**预测目标不仅决定模型能否预测，还会决定模型眼中的世界具有怎样的几何。**

> ## 能预测未来，不等于容易规划未来。

这句话是理解第二篇论文的钥匙，也恰好照亮了第一篇论文真正做成了什么。

本文沿着下面这条线继续追踪 JEPA：

```text
I-JEPA：在表示空间预测
    ↓
LLM-JEPA：让同一知识的两种语言表达在表示空间中可预测
    ↓
Value-Guided JEPA：让表示空间不仅可预测，而且适合规划
```

# 第一条延续：当 JEPA 遇到语言模型

## 它没有取代 next-token prediction

看到 “LLM-JEPA” 这个名字，很容易产生一个过于宏大的想象：语言模型不再逐 token 预测，而是像世界模型一样直接在语义空间里预测未来。

论文实际采取的路线更克制，也更务实：**标准的 next-token prediction（NTP）仍然保留，JEPA 只是额外增加一个序列级的表示预测目标。**

例如，输入是一段自然语言需求，输出是与之对应的正则表达式或 SQL。作者把它们视作同一知识的两种视图：

- `Text`：人类用自然语言描述“我要什么”；
- `Code`：程序语言精确表达“它如何实现”。

训练目标可以简写为：

```text
L = L_NTP + λ · [1 - cos(Pred(Enc(Text)), Enc(Code))]
```

第一项照常训练模型生成正确的下一个 token。第二项则要求：从 `Text` 得到的表示，经 `Pred` 转换后，应当靠近 `Code` 的整体表示。论文随后把“双视图”推广到问题与答案、数学题与推理结果、上下文与正确续写，以及互为释义的句子。

这件事的直觉并不复杂。只用 token loss 时，模型只要一步步把答案吐对即可；加入 JEPA 目标后，输入末端的隐藏状态还要提前形成一个足以预示答案整体语义的表示。它不只被问“下一个词是什么”，还被问“你现在对整件事的理解，能否指向正确答案所在的语义区域？”

## 这里的 `Pred` 到底是什么

这是整篇 [LLM-JEPA 论文](https://arxiv.org/pdf/2509.14252)最容易被名字误导的地方。

`Pred` 是 `Predictor` 的缩写，但它不是另起一套网络，也不是一个在部署阶段持续模拟未来的物理引擎。作者在 `Text` 末尾追加若干个特殊的 `[PRED]` token，继续复用同一个 LLM 做前向计算，最后一个 `[PRED]` token 的隐藏状态就是预测出来的序列表示。

可以把它想成让模型在回答前留出几块“只用于组织整体意思的草稿纸”。这些 token 不负责生成可读文字，它们负责把输入压成一个能够靠近目标表示的向量。`k=0` 时甚至没有额外预测 token，而是直接对齐两边的表示。

训练时，论文还用 block-causal attention mask 阻止 `Text` 和 `Code` 互相偷看，在一次组合计算中拿到相互独立的输入表示与目标表示。推理时，整条 JEPA 支路以及 `[PRED]` token 都被移除，模型仍然按普通自回归方式生成。因此它增加的是训练约束，不增加在线推理步骤。

从[公开代码](https://github.com/galilai-group/llm-jepa)看，这套实现也没有照搬 I-JEPA 的完整配方：没有 EMA target encoder，目标表示没有被 `detach`，JEPA 损失的梯度会同时流向两侧。它更接近“共享编码器上的成对表示一致性正则”，而不是经典 I-JEPA 那种 context encoder、predictor 与慢速 target encoder 的非对称结构。

这个区别不是咬文嚼字。论文附录做了一个非常关键的实验：去掉 NTP，只保留 JEPA 目标，模型会生成空输出。换句话说，**生成损失不是一个可有可无的旧零件，而是防止整个语言能力被表示对齐目标带偏的锚点。** 作者也因此把 JEPA 项称为对生成目标的 regularization term。

## 它带来了什么

论文在多个 1B–8B 级模型和任务上报告了稳定的正向结果。以 Llama-3.2-1B 为例：

| 任务 | 普通 NTP | LLM-JEPA | 绝对提升 |
| --- | ---: | ---: | ---: |
| NL-RX-SYNTH | 57.29 | 71.46 | +14.17 |
| GSM8K | 32.36 | 36.36 | +4.00 |
| Spider | 47.52 | 50.55 | +3.03 |
| HellaSwag | 69.40 | 70.51 | +1.11 |

最明显的收益出现在“自然语言描述 → 正则表达式”这类天然具有双视图结构的任务上。模型从文字规格映射到形式语言，恰好非常适合用一个整体表示预测另一个整体表示。换到更强的基线或语义关系较松的任务，增益会明显缩小：例如 Qwen3-1.7B 在 GSM8K 上只从 44.32 提升到 45.00。

作者还观察到，加入 JEPA 项后，输入与输出表示之间的差值被压进更窄、更接近线性的子空间。这是一个有趣现象，但不能倒果为因：损失本来就在直接拉近两个表示，所以几何变得整齐首先是优化目标的结果；现有实验展示的是“几何变化与准确率提升同时出现”，还没有证明前者必然导致后者。

计算代价也要放在桌面上。主设置中，一个 epoch 的训练计算大约是普通微调的两倍；随机丢弃一部分 JEPA loss 的受限实验可把平均成本降到约 1.25 倍，并在等 PFLOPs 曲线上保持优势，但主结果并不是全面的等算力比较。LLM-JEPA 还为 `k` 和 `λ` 搜索了更多组合，若配置选择和显著性检验没有严格隔离 validation/test，就可能乐观估计收益。论文的通用预训练实验也明确仍是 preliminary，而不是互联网规模预训练已经验证成功。

所以，我更愿意把这篇论文的结论收在一个准确的位置：

> LLM-JEPA 没有把语言模型变成一个完整的 JEPA 世界模型；它证明了 JEPA 式的跨视图表示预测，可以成为自回归训练的一种有效辅助约束。

它的延续在于“如何学习表示”，而不是“如何用表示规划行动”。后一个问题，恰好由第二篇论文接住。

# 从预测到规划，中间隔着一堵墙

设想一台机器人站在迷宫里。它有一个非常准确的世界模型：给定当前位置和动作，它能够预测下一时刻会到哪里。然后我们让规划器不断尝试动作序列，选择那个“预测终点离目标最近”的方案。

听起来已经万事俱备，但问题可能出在“最近”两个字上。

目标就在墙的另一侧。从平面坐标看，当前位置和目标只差半米；从行动上看，机器人必须先远离目标，绕过长墙，再从另一侧回来。一个普通的欧氏距离会持续告诉规划器：“贴着墙已经非常接近了。”于是规划器容易卡在墙边的局部最优点，不愿意接受那段“先变远、后变近”的绕路。

如果编码器学到的潜空间也保留了这种错误几何，世界模型即便把每一步都预测对，规划器看到的仍是一张不好用的地图。

这里必须拆开两个经常被混为一谈的能力：

- **可预测性（predictability）**：给定当前状态和动作，能否准确预测下一状态；
- **可规划性（plannability）**：潜空间中的距离与梯度，能否引导优化器找到真正可达、代价更低的动作序列。

预测模型回答“做了这个动作会发生什么”。规划器还需要回答“在所有可能的未来里，哪条路值得走”。前者准确，不会自动让后者容易。

# 第二条延续：让价值函数重画潜空间地图

## 这一次，Predictor 真的是运行中的世界模型

[Value-Guided Action Planning with JEPA World Models](https://arxiv.org/html/2601.00844)研究的是动作条件 JEPA。它的基本结构可以写成：

```text
z_t        = E(s_t)
ẑ_{t+1}   = Pred(z_t, a_t)
```

编码器 `E` 把当前图像状态压成 512 维表示，独立的 1.3M 参数 MLP Predictor 接收状态表示和动作，预测下一状态表示。训练中的潜空间预测损失，让 `ẑ_{t+1}` 靠近真实下一帧的 `E(s_{t+1})`。

部署时，这个 Predictor 不会被扔掉。模型预测控制（MPC）配合 MPPI，在潜空间里批量展开候选动作序列：Predictor 负责想象每一步会到哪里，距离或价值函数负责给这些未来打分，然后只执行当前最合适的一小步，再观察、重规划。

同样叫 `Pred`，这里的工程职责已经与 LLM-JEPA 完全不同：前者是训练期的表示对齐机制，后者是推理期反复调用的动力学模型。

## 把“离目标多远”训练成“还要付出多少代价”

标准做法通常直接最小化预测状态与目标状态之间的 latent distance。论文认为，这个距离只是“表征像不像”，未必表示“经过动作能否到达”。于是作者反过来规定潜空间应该长成什么样：让状态到目标的距离近似 goal-conditioned value function 的负值。

```text
V(s, g) = - ||E(s) - E(g)||
```

如果从状态 `s` 到目标 `g` 需要很多步，距离就应该大，价值就应该低；如果很快可以到达，距离就应该小，价值就应该高。这样一来，墙两侧虽然视觉上和坐标上很接近，只要真实行动必须绕远，它们在潜空间里就不应被放得太近。

作者使用 IQL 风格的 expectile TD loss 学这个目标条件价值。直觉上，它不要求模型穷举所有动作，而是利用离线轨迹中的状态转移，反复校正“从这里到目标还要付出多少代价”。下一状态的 bootstrap target 使用 stop-gradient，但这里没有 I-JEPA 式的 EMA teacher；被固定的是 TD 目标的梯度路径，不是另一套慢速编码器。

论文进一步把对称的欧氏距离换成 quasi-distance。普通距离默认 `d(s, g) = d(g, s)`，但现实中的可达代价经常带方向：下坡容易上坡难、顺流容易逆流难、把杯子推下桌容易放回桌上难。quasi-distance 允许两个方向不同，因此更有能力表达控制问题中的非对称性。即便论文里的简化环境未必强烈需要这种方向性，quasi-distance 版本仍然取得了最好结果。

## 最反直觉的结果：联合训练反而更差

如果按照“JEPA 世界模型”的直觉，我们可能会同时优化两件事：一边让 Predictor 准确预测下一状态，一边让 Encoder 的距离符合价值函数。论文确实测试了这种联合方案，但结果并不好。

表现最好的 `VF_quasi` 使用的是分阶段训练（论文记为 `Sep`）：

1. 先只用 value loss 塑造状态 Encoder，让潜空间形成适合目标到达任务的几何；
2. 冻结这个潜空间；
3. 再训练动作编码器和 Predictor，去拟合已经固定的潜空间动力学；
4. 规划时用 Predictor rollout，用 quasi-distance 评价候选未来。

与最佳标准 JEPA 基线 `pred_VCReg` 相比，成功率为：

| 环境 | pred_VCReg | VF_quasi（Sep） | 绝对提升 |
| --- | ---: | ---: | ---: |
| Wall Small（WS） | 0.55 | 0.71 | +0.16 |
| Wall Big（WB） | 0.89 | 0.96 | +0.07 |
| Maze | 0.54 | 0.63 | +0.09 |

而把价值损失和预测损失联合起来的 `VF_quasi_pred`，三个环境分别只有 0.61、0.85 和 0.43，全面低于分阶段版本。加入 VCReg 也没有改善结果。

这组实验透露出一个非常值得追踪的信号：**“容易预测的表示”与“容易规划的表示”至少在当前训练方法下并不天然一致，两个目标甚至可能争夺潜空间的几何。** 动力学预测希望忠实保留对下一状态有用的变化；价值塑形则希望把状态按目标可达代价重新排列。联合优化并不会自动找到两者的最佳折中。

当然，证据边界必须说清。这是一篇 7 页的 workshop 工作，实验只有简化的 Wall 和 Maze 环境；主表没有多随机种子均值、标准差或误差条，也没有报告 latent prediction accuracy、训练 FLOPs、在线规划延迟。Wall 规划每次可用 2000 个 MPPI 扰动，Maze 也要用 500 个、规划 horizon 为 100，在线搜索并不轻。论文尚未证明这套方法能直接扩展到真实机器人、高维接触动力学或随机环境。

因此，它更像一张清晰的路标，而不是已经铺好的高速公路：**如果世界模型最终要服务规划，仅仅让未来状态可预测还不够，潜空间本身必须带有任务需要的价值结构。**

# 三个 Predictor，其实是三种角色

JEPA 系列论文经常复用 `Encoder`、`Target`、`Predictor` 这些词，但相同名称不代表相同的系统职责。把三类工作放在一起，区别会非常清楚：

| 工作 | Predictor 的输入与输出 | 是否独立模块 | 推理时是否保留 | 主要作用 |
| --- | --- | --- | --- | --- |
| I-JEPA | 可见区域表示 → 被遮挡区域表示 | 是 | 下游任务通常不保留 | 用预测任务逼出通用视觉表征 |
| LLM-JEPA | 文本表示 → 代码、答案或续写的整体表示 | 否，复用同一 LLM 的 `[PRED]` token | 否 | 训练期跨视图语义对齐 |
| Value-Guided JEPA | 当前状态表示 + 动作 → 下一状态表示 | 是，独立 MLP | 是 | 为 MPC/MPPI 提供潜空间动力学 rollout |

所以，读论文时不能只问“有没有 Predictor”，还要追问三个问题：

1. 它到底在预测被遮挡内容、另一种语义视图，还是动作之后的状态？
2. 它是塑造 Encoder 的训练脚手架，还是部署时真正运行的世界模型？
3. 目标表示由谁产生，梯度是否回传，是否存在 stop-gradient 或 EMA teacher？

只要这三个问题没有说清，“JEPA”很容易变成一个看似统一、实际含义不断漂移的标签。

# 从“预测什么”走向“为了什么而预测”

把两篇论文并排看，最有意思的并不是它们共享了 JEPA 这个名字，而是它们都在用训练目标改造表示空间。

LLM-JEPA 的做法是：如果自然语言规格与代码实现表达的是同一件事，就强迫前者的整体表示能够预测后者。结果是输入与输出之间的语义映射更集中、更容易线性化。在这里，目标函数告诉模型：**语法可以不同，但共享的知识应当靠近。**

Value-Guided JEPA 的做法则是：如果两个状态之间必须走很长的路，就算它们视觉上相似、坐标上接近，也不应当在规划空间里靠得太近。在这里，目标函数告诉模型：**外观可以相近，但行动代价不同的状态必须被拉开。**

前者在消除不重要的表达差异，后者在放大对决策重要的可达性差异。它们共同提醒我们：表示学习从来不是把世界“客观地压缩”进一个向量。模型会保留什么、忽略什么、把谁放在谁旁边，取决于我们要求它完成什么预测任务。

这也让我重新理解“世界模型”四个字。一个世界模型至少有三层能力：

| 层次 | 核心问题 | 仅做到这一层的局限 |
| --- | --- | --- |
| 表示 | 世界中哪些差异值得保留？ | 可能有语义，但没有动力学 |
| 预测 | 做了动作，世界会怎样变化？ | 可能预测准确，但搜索地形糟糕 |
| 规划 | 哪条未来路径更可达、代价更低？ | 还需要与具体目标和控制闭环结合 |

JEPA 最初最鲜明的主张，是从原始信号重建转向抽象表示预测。现在，这条路线继续向前时遇到了第二次转向：从“表示能否预测未来”转向“表示能否帮助我们在未来中做选择”。

而一旦进入选择，世界就不再只有事实结构，还要有价值结构。距离不再只是相似度，可能还是时间、风险、能量、可达性与不可逆性的混合物。对一个生成模型来说，把两个同义句放近也许足够；对一台要穿过迷宫的机器人来说，墙的存在必须刻进表示空间。

# 仍然值得保留的几个问号

这两篇论文都给出了漂亮的方向，但距离一个统一、规模化的结论还有明显空白。

对 LLM-JEPA，最重要的问题是：收益究竟来自 JEPA 特有机制，还是来自更一般的“让输入端隐藏状态提前编码答案语义”的监督正则？要回答它，还需要与普通 representation alignment、双向生成、BYOL/SimSiam 式目标、多任务学习等进行等算力比较，并在更大规模预训练和开放式生成中验证。

对 Value-Guided JEPA，最重要的问题是：当环境变得随机、奖励稀疏、离线数据覆盖不足，或者机器人需要处理接触、遮挡与长时序任务时，价值塑形的潜空间是否仍然稳定？论文自己也指出，远距离目标的 TD 信号更弱，IQL 在随机环境中可能有偏，而 prediction-based JEPA 反而可能在随机动力学下更稳健。

更长远的问题，是能否让一个表示空间同时兼顾：

- 对感知任务足够通用；
- 对动力学预测足够忠实；
- 对目标规划足够平滑；
- 对不同任务又不至于每次重学一套几何。

第二篇论文里“分阶段胜过联合训练”的结果，说明这件事远没有被自然解决。未来真正强大的世界模型，可能不只需要更大的 Predictor，也需要能按目标重构距离、按任务切换几何的机制。

# 写在最后

从 I-JEPA 到这两篇后续工作，我们看到的不是一条整齐、单向的升级路线，而是 JEPA 思想在不同领域里不断变形：

- I-JEPA 用隐藏区域预测塑造视觉 Encoder；
- LLM-JEPA 用跨视图预测约束语言模型的语义表示；
- Value-Guided JEPA 则把价值与可达性写进潜空间，再让动力学模型在这张地图上滚动。

第一篇告诉我们，预测目标可以改变语言表示的组织方式；第二篇进一步告诉我们，世界模型最后好不好用，不只取决于它预测得准不准，还取决于它把“远近”定义成了什么。

也许 JEPA 接下来真正值得追踪的问题，已经不只是“能不能少预测一些像素、多预测一些抽象”，而是：**我们希望一个智能体为了什么目的，学会怎样的抽象。**

> 能预测未来，是世界模型的起点；能在未来里找到一条路，才是规划的开始。
